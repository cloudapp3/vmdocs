# Конфигурация

vmflow управляется единым YAML-файлом. `vmflow run` по умолчанию загружает platform user config path:

```bash
vmflow run
```

При необходимости путь можно переопределить:

```bash
vmflow run -config /path/to/config.yaml
```

При перезагрузке активный путь конфигурации перечитывается и применяется новое желаемое состояние (см. [Правила и жизненный цикл](./rules)).

## Полный пример

```yaml
version: 1
language: en
control_port: 19090
udp_max_sessions: 256

log:
  level: info
  format: text # text or json

stats:
  persist: false
  flush_interval: 60s

# Управление всегда привязано к 127.0.0.1; задаётся только порт.
# The CLI/TUI can pass the token with -token or VMFLOW_CONTROL_TOKEN.
auth:
  enabled: false
  tokens:
    - name: admin
      token: change-me
      role: admin

rules:
  - rule_id: ssh-forward
    name: ssh-forward
    protocol: tcp
    listen_addr: 0.0.0.0
    listen_port: 2201
    target_addr: 127.0.0.1
    target_port: 22
    enabled: true
    bandwidth_limit:
      rate: 100 Mbps
    traffic_quota:
      daily: 100 GB
      monthly: 1 TB
      timezone: Asia/Shanghai
      action: block
    speed_limit: 0 # старый лимит B/s на соединение
    max_conn: 0
    source_ip_mode: allowlist
    source_ips:
      - 203.0.113.8
      - 198.51.100.0/24
      - 2001:db8:100::/48
    remark: example
```

## Поля верхнего уровня

| Поле | Описание |
| --- | --- |
| `version` | Версия схемы конфигурации. На данный момент `1`. |
| `control_port` | Локальный порт управления. По умолчанию `19090`; адрес всегда `127.0.0.1`. |
| `log` | Структурированное журналирование — `level` и `format`. |
| `auth` | Аутентификация по Bearer-токену с ролями `admin` / `viewer`. |
| `bot_token`, `bot_chat` | Telegram-бот — см. [Telegram-бот](./telegram-bot). |
| `rules` | Правила перенаправления (см. `rules[]` ниже). |

## `log`

| Поле | Значения |
| --- | --- |
| `level` | Уровень журналирования (например, `debug`, `info`, `warn`, `error`). |
| `format` | `text` или `json`. |

## `auth`

Аутентификация Bearer token для управления через CLI/TUI.

| Поле | Описание |
| --- | --- |
| `enabled` | Требовать настроенные token для локальных инструментов управления. |
| `tokens[].name` | Метка токена (не используется для аутентификации). |
| `tokens[].token` | Строка Bearer-токена. |
| `tokens[].role` | `admin` (чтение + запись) или `viewer` (только чтение). |

## `rules[]`

Каждая запись описывает одно правило перенаправления.

| Поле | Описание |
| --- | --- |
| `rule_id` | Стабильный уникальный ID, используется для сравнения при перезагрузках. |
| `name` | Человекочитаемое имя. |
| `protocol` | `tcp`, `udp` или `tcp+udp`. |
| `listen_addr` | Адрес прослушивания (например, `0.0.0.0`). |
| `listen_port` | Порт прослушивания. |
| `target_addr` | Адрес вышестоящего узла для перенаправления. |
| `target_port` | Порт вышестоящего узла. |
| `enabled` | При `false` правило остаётся в конфигурации, но не запускается. |
| `speed_limit` | Ограничение скорости на соединение в байтах/сек (`0` = без ограничений). |
| `max_conn` | Максимум одновременных соединений (`0` = без ограничений). Новые соединения сверх лимита закрываются. |
| `idle_timeout` | Тайм-аут простоя на соединение в секундах (`0` = по умолчанию 5 минут). Изменение перезапускает правило. |
| `source_ip_mode` | Режим допуска по IP-адресу источника: `off`, `allowlist` или `denylist`. Если поле не задано, используется `off`. |
| `source_ips` | Литеральные адреса IPv4/IPv6 или CIDR для выбранного режима. Не более 256 записей на правило. |
| `remark` | Произвольное примечание. |

## Политика доступа по IP-адресу источника

`allowlist` принимает только источники, совпадающие с `source_ips`. `denylist` отклоняет совпадающие источники и принимает остальные. Для активного списка разрешений или запретов нужна хотя бы одна запись; имена хостов, некорректные адреса, пустые записи и списки длиннее 256 записей отклоняются.

TCP проверяет адрес socket peer до расходования лимита `max_conn` и соединения с целевым узлом. UDP выполняет проверку до создания сессии и расходования лимитов UDP-сессий правила или всего процесса. Изменение режима или эффективного набора записей перезапускает правило и закрывает существующие TCP-соединения и UDP-сессии, поэтому новая политика применяется сразу.

Политика видит фактический адрес socket peer. За NAT или L4-прокси это может быть адрес шлюза или прокси, а не исходного клиента. vmflow не доверяет перенаправленным HTTP-заголовкам или метаданным PROXY protocol. Для первого уровня защиты от крупных атак используйте облачный firewall, security group или firewall узла.

## Общие лимиты скорости и квоты трафика

`bandwidth_limit` ограничивает суммарный трафик всего `rule_id`. Все TCP-соединения и UDP-сессии правила используют общие направленные корзины, включая оба протокола `tcp+udp`. `rate` задаёт одинаковые upload/download лимиты; для асимметрии используйте `upload` и `download`. Пропущенное направление не ограничено, burst vmflow рассчитывает автоматически.

`bps`/`Kbps`/`Mbps`/`Gbps` означают bit/s, а `B/s`/`KB/s`/`MB/s`/`GB/s`/`KiB/s`/`MiB/s` — byte/s; регистр важен. `traffic_quota.daily` и `monthly` суммируют успешно переданные upload + download данные. Поддерживаются десятичные `GB`/`TB`, двоичные `GiB`/`TiB` и IANA `timezone`. `action` можно опустить; сейчас поддерживается только `block`.

Квоты сохраняются в `quota-state.json` даже при `stats.persist: false` и не сбрасываются после перезапуска или повторного добавления того же `rule_id`. `language` принимает только `en` или `zh-CN`. DNS не настраивается: после временного сбоя системного резолвера используются `223.5.5.5:53`, затем `119.29.29.29:53`; ответ `NXDOMAIN` fallback не запускает.

::: tip
Протоколы `http` и `https` присутствуют в исходниках, но отключены в текущей сборке. Они отклоняются при валидации. См. [справочник по перенаправлению](./forwarding).
:::

## Прочие поля

Кроме описанного, конфигурация принимает поля Telegram bot и зарезервированные поля ACME/сертификатов. Активные настройки bot описаны в [Telegram Bot](./telegram-bot).

| Поле | Статус |
| --- | --- |
| `bot_token`, `bot_chat` | Активно — см. [Telegram-бот](./telegram-bot). |
| `acme_*`, `cert_cache_dir`, `cert_review.*` | Зарезервировано (игнорируется в текущей сборке). |
