# Установка

`vmflow` поставляется как одиночный статический бинарный файл для Linux и macOS (`amd64` и `arm64`). Получите его из GitHub Releases через инсталлятор или соберите из исходников.

В релизах публикуются переносимые архивы, а не управляемые дистрибутивом пакеты `.deb` или `.rpm`. Используйте установщик ниже либо распакуйте архив вручную.

## Рекомендуемая пользовательская установка

```bash
VMFLOW_BIN_DIR="$(
  curl -fsSL https://raw.githubusercontent.com/cloudapp3/vmflow/main/install.sh \
    | bash -s -- --version v0.2.0-rc.4 --print-install-dir
)" \
  && [ -n "$VMFLOW_BIN_DIR" ] \
  && [ "${VMFLOW_BIN_DIR#/}" != "$VMFLOW_BIN_DIR" ] \
  && [ -x "$VMFLOW_BIN_DIR/vmflow" ] \
  && export PATH="$VMFLOW_BIN_DIR:$PATH"
```

Команда фиксирует текущий prerelease и сразу добавляет выбранный каталог в PATH текущей оболочки. Чтобы следовать за последней стабильной версией, уберите `--version v0.2.0-rc.4`. Сейчас инсталлятор без версии выбирает `v0.1.1`, где ещё нет MCP и политик Source IP, описанных в этой документации.

## Системная установка

Установка в `/usr/local/bin` без запуска всего загруженного скрипта от root:

```bash
curl -fsSL https://raw.githubusercontent.com/cloudapp3/vmflow/main/install.sh \
  | bash -s -- --version v0.2.0-rc.4 --system
```

Если обычный пользователь задаёт `--system`, инсталлятор проверяет sudo до загрузки и использует его только для проверок и записи в целевой каталог. Новая соседняя конфигурация принадлежит root и имеет режим `0600`; используйте команды проверки и запуска с root/sudo, которые выводит инсталлятор.

Чтобы установить другой релиз, измените тег для `--version`:

```bash
curl -fsSL https://raw.githubusercontent.com/cloudapp3/vmflow/main/install.sh | bash -s -- --version v0.2.0-rc.4
```

### Параметры инсталлятора

| Параметр | Описание |
| --- | --- |
| `--version <tag>` | Установить конкретный тег релиза. По умолчанию — последняя стабильная версия. |
| `--dir <path>` | Использовать явно заданный каталог; также доступно через `VMFLOW_INSTALL_DIR`. |
| `--system` | Установить системно в `/usr/local/bin`, используя sudo только при необходимости. |
| `--skip-verify` | Пропустить проверку контрольной суммы SHA-256. |
| `--no-modify-path` | Не добавлять автоматически выбранный пользовательский каталог в файл запуска оболочки. |
| `--print-install-dir` | После успешной установки вывести в stdout только выбранный каталог. |
| `--uninstall` | Удалить через `vmflow uninstall`, если команда доступна; для старого или отсутствующего бинарника использовать shell fallback. |
| `-h, --help` | Показать справку. |

### Каталог и PATH

Без `--dir` инсталлятор сначала повторно использует стандартную существующую установку vmflow с соседним файлом конфигурации. Новая установка root использует `/usr/local/bin`. Для обычного пользователя предпочтение отдаётся `~/.local/bin` или `~/bin`, если каталог уже входит в PATH, иначе используется `~/.local/bin`.

При автоматической пользовательской установке инсталлятор при необходимости добавляет один идемпотентный блок PATH в `.zshrc`, `.bashrc` или `.profile` и выводит точную команду перезагрузки. Текущую оболочку изменить нельзя, поэтому рекомендуемая команда получает `--print-install-dir` и сразу выполняет export. Явные `--dir` и `VMFLOW_INSTALL_DIR` никогда не изменяют файлы запуска оболочки.

### Конфигурация и совместимость архивов

Инсталлятор скачивает архив GitHub Release и по умолчанию проверяет `checksums.txt` по SHA-256. Поддерживаются как текущий `config.yaml` в корне архива, так и старый `examples/config.yaml`. Первая установка создаёт рядом с бинарником `config.yaml` с режимом `0600`; обновления заменяют только бинарник и сохраняют конфигурацию и правила перенаправления.

Для приватных релизов или повышения лимитов GitHub API задайте `GITHUB_TOKEN` или `GH_TOKEN`.

## Сборка из исходников

Требования: [Go](https://go.dev/dl/) (свежая версия, см. `go.mod`).

```bash
git clone https://github.com/cloudapp3/vmflow.git
cd vmflow
go build -trimpath -o vmflow ./cmd/vmflow
```

Либо через Makefile:

```bash
make build
```

## Проверка установки

```bash
vmflow version
vmflow version -json
```

## Обновление vmflow

После установки из тегированного релиза (v0.1.1 и новее) `vmflow` может обновлять сам себя:

```bash
vmflow update --check            # проверить наличие нового релиза
vmflow update                    # установить самый свежий релиз
vmflow update --version v0.2.0-rc.4 # установить текущий prerelease
```

Подробности, флаги и платформенные особенности — см. [`vmflow update`](./update).

## Удаление установки, созданной инсталлятором

```bash
curl -fsSL https://raw.githubusercontent.com/cloudapp3/vmflow/main/install.sh \
  | bash -s -- --uninstall
```

После успешного удаления бинарника команда также удаляет точный блок PATH, созданный инсталлятором. Используйте `sudo bash -s -- --uninstall` только для системной установки, принадлежащей root. Объём очистки и правила сохранения описаны в [`vmflow uninstall`](./uninstall).
