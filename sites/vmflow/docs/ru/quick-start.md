# Быстрый старт

Это руководство устанавливает стабильный vmflow v0.3.0, создаёт первое проверенное правило через `vmflow init` и опрашивает работающий демон через CLI.

## 1. Установка

Установите `v0.3.0` для текущей оболочки (Linux/macOS):

```bash
VMFLOW_BIN_DIR="$(
  curl -fsSL https://raw.githubusercontent.com/cloudapp3/vmflow/main/install.sh \
    | bash -s -- --version v0.3.0 --print-install-dir
)" \
  && [ -n "$VMFLOW_BIN_DIR" ] \
  && [ "${VMFLOW_BIN_DIR#/}" != "$VMFLOW_BIN_DIR" ] \
  && [ -x "$VMFLOW_BIN_DIR/vmflow" ] \
  && export PATH="$VMFLOW_BIN_DIR:$PATH"
```

Проверка:

```bash
vmflow version -json
```

При необходимости инсталлятор также настраивает PATH для будущих сеансов поддерживаемых оболочек. Системная установка через `--system`, выбор каталога, проверка контрольных сумм и сборка из исходников описаны в разделе [Установка](./installation).

## 2. Инициализация vmflow

Запустите мастер первого использования:

```bash
vmflow init
```

Первым выбирается язык: `1` — English, `2` — упрощённый китайский. Затем выберите рекомендуемый системный сервис, foreground в текущем терминале или сохранение без запуска. Мастер создаёт проверенное правило, включает аутентифицированное локальное управление и записывает правильный system/user config для выбранного режима.

Режим сервиса устанавливает, включает и уже запускает vmflow, поэтому не запускайте второй foreground-процесс. Foreground-режим также уже работает и остаётся привязанным к текущему терминалу. Используйте `vmflow run` позже только после сохранения без запуска.

## 3. Опрос

Из другого терминала опросите локальный демон встроенным CLI:

```bash
vmflow ctl rules
vmflow ctl stats
vmflow ctl metrics
vmflow ctl precheck
```

## 4. Открытие терминального интерфейса

Для нативной системной службы используйте команду по умолчанию. Сначала она проверит, что локальная служба установлена и работает:

```bash
vmflow tui
```

В foreground-режиме оставьте терминал демона открытым и явно укажите адрес запущенного вручную процесса:

```bash
vmflow tui -addr http://127.0.0.1:19090
```

Явный `-addr` пропускает проверку нативной службы. Нажмите <kbd>Tab</kbd> для переключения между режимами Dashboard, Rules и Detail. См. [Панель TUI](./tui-guide).

## 5. Перезагрузка после правки конфигурации

Посмотрите активный путь конфигурации через `vmflow status`, отредактируйте файл и примените новое состояние:

```bash
vmflow status
vmflow ctl reload
```

Перезагрузка сначала запускает [предпроверку](./precheck); при ошибках изменение отклоняется, а работающие правила остаются нетронутыми.
